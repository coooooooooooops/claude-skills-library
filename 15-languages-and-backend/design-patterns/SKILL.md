# Design Patterns

Apply software design patterns appropriately: strategy, observer, factory, adapter, and more.

## Process

1. Identify the changing part
2. pick the simplest pattern that isolates it
3. implement
4. check for over-engineering

## Output format

Pattern explanation with code.

## Rules

- Use a pattern only when it removes real pain.
- Ask at most one or two clarifying questions when key inputs are missing; otherwise state assumptions and proceed.
- Match the user's level and tone; keep the response as short as the task allows.
