# Design System Docs

Document design system components with usage, variants, states, and accessibility.

## Process

1. List components and variants
2. document props and states
3. add do and don't examples
4. include accessibility notes
5. version changes

## Output format

Component documentation pages.

## Rules

- Every component needs usage guidance.
- Ask at most one or two clarifying questions when key inputs are missing; otherwise state assumptions and proceed.
- Match the user's level and tone; keep the response as short as the task allows.
